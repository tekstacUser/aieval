===============================================================================
TEST CASE 1 : REQUIREMENT UNDERSTANDING AND ARCHITECTURE PLANNING
===============================================================================

Max Marks : 10

Checks whether the learner's prompts show they understood the overall
architecture BEFORE asking the AI to generate artifacts: a lightweight
Kubernetes-hosted Flask gateway calling out to an Ollama runtime that stays
on the VM/host (not duplicated into every pod), reached from Minikube via
host.minikube.internal, with the gateway exposing /generate, /health and
/ready and serving the phi3:mini model.

Reference checklist:

- Learner's prompts state that Ollama itself must remain on the VM/host and
  only the Flask gateway should be replicated inside Kubernetes.
- Learner's prompts describe the need for the gateway to reach Ollama across
  the Minikube/VM boundary (e.g. via host.minikube.internal or an equivalent
  reachable OLLAMA_URL), rather than assuming localhost works inside a pod.
- Learner's prompts specify the required gateway contract: a POST
  /generate inference route plus /health and /ready endpoints, and that
  phi3:mini is the model to be served.
- Learner's prompts show awareness of the Kubernetes objects the design
  needs end to end (Deployment, Service, HPA) rather than asking for pods in
  isolation.

===============================================================================
TEST CASE 2 : PROMPT QUALITY FOR BUILD, DEPLOYMENT AND DEBUGGING
===============================================================================

Max Marks : 10

Checks the quality and specificity of the learner's prompts while asking the
AI to help write and deploy the artifacts: the Flask app.py/Dockerfile, the
Kubernetes Deployment/Service/HPA manifests, and any debugging prompts used
to resolve build, connectivity, or scheduling problems along the way.

Reference checklist:

- Learner's prompts request concrete build artifacts (app.py, requirements.txt,
  Dockerfile) with specific, relevant details (e.g. correct port 8070, the
  OLLAMA_URL/OLLAMA_MODEL environment variables, CPU_WORK_MS workload knob)
  rather than a vague "build me a gateway" ask.
- Learner's prompts request Kubernetes manifests (Deployment, Service, HPA)
  with meaningful parameters called out (replica counts, resource
  requests/limits, probes, selector labels, HPA min/max/CPU target) instead
  of accepting defaults blindly.
- When something didn't work (image not found, pod not ready, service not
  reachable, Ollama unreachable from the pod, port already in use, etc.),
  the learner's prompts describe the actual symptom/error and ask the AI to
  help diagnose it, showing real troubleshooting rather than repeating the
  same prompt.
- Prompts show the learner adapting instructions to their own environment
  (e.g. choosing an open local port for port-forwarding, confirming Ollama
  is listening on 0.0.0.0) rather than only copying generic instructions.

===============================================================================
TEST CASE 3 : VERIFICATION AND VALIDATION STRATEGY
===============================================================================

Max Marks : 10

Checks whether the learner's prompts show a deliberate plan to verify the
system actually works end to end: inference correctness, health/readiness,
autoscaling behavior under load, and resilience to pod failure.

Reference checklist:

- Learner's prompts ask for or describe testing the /generate endpoint with
  a real prompt and checking the response, not just assuming it works after
  deployment.
- Learner's prompts ask for or describe checking /health and /ready (locally,
  inside the cluster, and/or through the port-forwarded endpoint).
- Learner's prompts address verifying the HPA — either how to observe
  autoscaling under simulated load, or how to confirm the HPA's target,
  replica range, and metric are correctly configured.
- Learner's prompts address verifying Kubernetes self-healing (e.g. asking
  what should happen if a pod is deleted, or how to confirm a replacement
  pod comes back and becomes ready).

===============================================================================
GENERAL SCORING RULES
===============================================================================

Full Marks

- The major criteria are explicitly demonstrated.

Partial Marks

- Learner prompts cover a subset of checklist items.
- Score proportionally to the fraction and strength of evidence.

Zero Marks

Award 0 for a testcase ONLY when:

- There is no usable learner prompt history; OR
- The learner's prompt history contains no relevant evidence for that testcase;
  OR
- The prompt history is unrelated to this handson.

The following conditions MUST NOT, by themselves, cause the entire testcase
to receive 0:

- Single-shot prompting.
- No iteration.
- No refinement.
- No follow-up question.
- No back-and-forth with the AI.
- No incremental development.

When one of these is absent, award 0 only for the specific scoring component
that requires that behavior, while continuing to score all other independently
demonstrated components.

A detailed, valid single-shot prompt can receive marks for requirement
understanding, prompt quality, technical specificity, and other explicitly
demonstrated criteria.

Do not infer missing evidence. Score only what is explicitly demonstrated.
